# phone_film for iOS — HIG 기반 설계 청사진

> 컨셉: 필름 색감(3D LUT)을 프리뷰와 촬영본에 입히는 카메라 앱.
> **필름 모드**(롤 24/36장을 다 찍을 때까지 필름 고정, 사진은 롤이 끝나야 현상되어 보임) / **단일 촬영 모드**(자유롭게 필름 교체, 즉시 확인).
> 이 문서는 구현 코드가 아니라 개발자용 청사진이다. SF Symbols 이름과 API 가용 버전은 구현 시 SF Symbols 앱과 Xcode로 한 번 더 확인할 것.

## 0. 전제와 결정 사항 (먼저 읽기)

| 항목 | 결정 | 이유 |
|---|---|---|
| 디자인 우선순위 | **HIG 우선.** 안드로이드판의 실버 카메라 바디(스큐어모픽)와 "상·하단 플레이트 고정" 규칙은 iOS판에 가져오지 않는다. | 요청이 Apple HIG의 엄격한 준수(탭 바, 내비게이션 바, 블러 머티리얼, 단일 틴트)였고, 둘은 구조적으로 양립하지 않는다. |
| 브랜드 유지 요소 | 필름 통(canister) 모티프, 프레임 카운터, 롤 잠금과 "현상" 경험, 필름 3종(텅스텐/골드/포레스트) | 앱의 정체성은 장식이 아니라 **개념**에 둔다. 장식은 걷어낸다(Clarity). |
| 안드로이드판과의 관계 | 기능 규칙(롤 잠금, 사진 숨김, 현상, 단일 모드 독립)은 **동일**. 화면 구성만 플랫폼 관습을 따른다. | 같은 상태 머신을 두 플랫폼이 공유해 동작을 일관되게 한다. |
| 최소 OS | iOS 17 (SwiftUI, `sensoryFeedback`, `numericText`, SwiftData) | iOS 26에서는 시스템 컴포넌트가 자동으로 Liquid Glass를 쓰므로 **바·시트를 직접 칠하지 않는다.** |
| 언어 | 한국어 기본, 영어 현지화 | 레이아웃은 Dynamic Type과 긴 문자열을 견디게 설계한다. |

## 1. 세 가지 원칙을 이 앱에 적용하는 방식

**Clarity (명료함)**
- 카메라 화면의 컨트롤은 4가지(모드, 필름, 셔터, 라이브러리 진입)로 제한한다. 그레인 텍스처, 금속 질감, 눈금 장식은 쓰지 않는다.
- 서체는 SF Pro만 쓴다. 크기가 아니라 **Text Style과 굵기**로 위계를 만든다(§3.1).
- 남는 공간은 비운다. 정보 밀도가 높은 곳은 롤 진행 표시 하나뿐이다.

**Deference (양보)**
- 내용(뷰파인더와 사진)이 주인공이다. 크롬(바, 시트)은 반투명으로 물러난다.
- 뷰파인더는 카메라 앱 관례대로 4:3, 연속 곡률(squircle) 모서리, 좌우 세이프 에어리어 안에 둔다.
- 다이내믹 아일랜드와 상태 바 영역(상단 세이프 에어리어)에는 어떤 컨트롤도 두지 않는다. 홈 인디케이터 영역은 탭 바가 차지한다.

**Depth (깊이)**
- 층 순서: ① 콘텐츠(뷰파인더, 사진) → ② 탭 바·내비게이션 바(`.bar` 머티리얼) → ③ 시트(`.regularMaterial`) → ④ 컨텍스트 메뉴·확인 대화상자(시스템).
- 시트는 뒤의 화면이 비쳐 보이는 분리형 디텐트를 쓰고, 상태를 잃지 않고 돌아올 수 있음을 공간으로 보여 준다.
- 화면 전환은 줌 전환(`navigationTransition(.zoom)`)과 시스템 푸시로 "어디서 왔는지"를 보존한다.

## 2. 정보 구조와 아키텍처

### 2.1 내비게이션 (표준 패턴만 사용)

```
TabView (Bottom Tab Bar, 3 destinations)
├─ Camera      [camera]            ← 시작 탭. 앱은 늘 여기서 열린다
│    └─ sheet: Film Drawer (필름 선택/장전)  [.medium / .large 디텐트]
│    └─ fullScreenCover: Develop (롤 종료 후 현상)   ← 롤이 끝났을 때만
├─ Library     [photo.on.rectangle]
│    └─ NavigationStack
│         └─ push: Roll Detail → push: Photo Viewer  (스와이프 뒤로 가기)
└─ Settings    [gearshape]
```

- 1차 목적지 3개만 탭에 둔다(HIG: 탭은 3~5개, 각 탭은 독립된 계층).
- 설정은 탭이다. 시트나 별도 모드가 아니다. 모든 탭은 자기 `NavigationStack`을 가지며, 탭을 다시 눌러 루트로 복귀한다.
- Android의 "한 화면 고정 레이아웃" 규칙은 이 플랫폼에서는 적용하지 않는다(§0).

### 2.2 기술 구성

| 영역 | 선택 | 메모 |
|---|---|---|
| UI | SwiftUI | `UIViewRepresentable`은 카메라 프리뷰 하나에만 사용 |
| 카메라 | AVFoundation (`AVCaptureSession`) | 프리뷰: `AVCaptureVideoDataOutput` → LUT 적용 → `MTKView`. 촬영: `AVCapturePhotoOutput`(고해상도) |
| LUT | Core Image `CIColorCubeWithColorSpace` (33³) 또는 Metal 3D 텍스처 | 프리뷰와 촬영본이 **같은 큐브 데이터**를 쓰게 해 색을 일치시킨다. 큐브 순서는 .cube(R이 가장 빨리 변함) 그대로 |
| 그레인 | `CIRandomGenerator` 기반, 필름 모드 촬영본에만 | 중간톤에 강하고 양 끝에서 약하게 |
| 영속 저장 | SwiftData(롤/모드/설정) + 앱 샌드박스 파일(촬영본) | 촬영 성공 후에 카운트 감소(순서 고정). 저장은 트랜잭션 |
| 갤러리 내보내기 | PhotoKit, **Add-Only 권한**(`NSPhotoLibraryAddUsageDescription`) | 현상 시점에 한꺼번에. 전부 성공해야 완료 처리, 실패 시 되돌리고 다음 실행에서 재시도 |
| 햅틱 | `.sensoryFeedback`(SwiftUI), 필요 시 `UIFeedbackGenerator` | §6 표 참고 |

### 2.3 상태 머신 (플랫폼 공통 규칙)

```
mode: film | single
roll: { film, total(24|36), shots[] } | nil      # nil이면 잠금 없음
잠금 = (mode == film && roll != nil)
셔터(film, roll==nil) → "필름을 먼저 넣어 주세요"
셔터(film, roll!=nil) → 사진 저장 성공 → shots.append → 마지막 장이면 현상
셔터(single)          → 즉시 사진 앱 저장, 롤은 그대로
재설치/데이터 삭제 → 롤 초기화(의도한 정책, 설정 화면 푸터에 명시)
```

## 3. 디자인 시스템

### 3.1 타이포그래피 (SF Pro, Dynamic Type 필수)

고정 pt를 코드에 쓰지 않고 **Text Style만** 쓴다.

| 용도 | Text Style | 기본 크기/굵기 | 사용처 |
|---|---|---|---|
| 화면 제목 | `.largeTitle` | 34 / Bold | Library, Settings의 큰 제목 |
| 섹션 제목 | `.title2` | 22 / Bold | 현상 화면 제목, 롤 섹션 |
| 헤드라인 | `.headline` | 17 / Semibold | 필름 이름, 카드 제목 |
| 본문 | `.body` | 17 / Regular | 안내 문장, 리스트 |
| 보조 | `.subheadline` | 15 / Regular | 필름 설명, 부제 |
| 각주 | `.footnote` | 13 / Regular | 푸터 설명, 날짜 |
| 캡션 | `.caption` | 12 / Regular | 프레임 번호, 뷰파인더 라벨 |
| 프레임 카운터 | `.largeTitle` + `.rounded` + `.monospacedDigit()` | 34 / Semibold | 남은 장수. `contentTransition(.numericText(countsDown: true))` |

- 위계는 굵기 3단계(Bold / Semibold / Regular)로만 만든다.
- 뷰파인더 위 글자는 반투명 배경(머티리얼) 위에 올려 어떤 장면에서도 대비를 확보한다.

### 3.2 색상 — 의미 기반 + Light/Dark 자동 대응

모든 색은 Asset Catalog의 Any / Dark / High Contrast 변형으로 정의한다. 코드에 16진수를 직접 쓰지 않는다.

| 의미 | 토큰 | Light | Dark | 사용 |
|---|---|---|---|---|
| 기본 배경 | `systemBackground` | #FFFFFF | #000000 | 탭의 루트 화면 |
| 그룹 배경 | `systemGroupedBackground` | #F2F2F7 | #000000 | Settings, Library |
| 카드 | `secondarySystemGroupedBackground` | #FFFFFF | #1C1C1E | 리스트 행, 카드 |
| 본문 글자 | `label` | #000000 | #FFFFFF | |
| 보조 글자 | `secondaryLabel` | 60% 회색 | 60% 흰색 | |
| 약한 글자 | `tertiaryLabel` | 30% 회색 | 30% 흰색 | 비활성, 푸터 |
| 구분선 | `separator` | 시스템 | 시스템 | |
| **틴트(단 하나)** | **`AccentColor` = "Film Amber"** | **#A35F00** | **#FFB340** | **상호작용 요소에만** |
| 파괴적 | `systemRed` | 시스템 | 시스템 | 삭제, 초기화 |

- **틴트는 앱 전체에서 한 가지**(Film Amber). 버튼, 토글, 선택된 세그먼트, 링크, 탭 바 선택 아이콘에만 쓴다.
  - Light #A35F00은 흰 배경에서 대비 약 4.8:1(본문 기준 4.5:1 이상). Dark #FFB340은 검정 위에서 높은 대비.
- **필름 3종의 색(파랑/금색/초록)은 UI 색이 아니라 콘텐츠**다. 필름 통 일러스트에서만 나타나며, 버튼이나 선택 표시의 색으로 쓰지 않는다. 선택 상태는 색이 아니라 체크 마크(`checkmark.circle.fill`)와 굵기로도 전달한다(색에만 의존하지 않기).
- 카메라 뷰파인더 화면은 Light/Dark와 무관하게 검정 바탕이다(콘텐츠 중심, 카메라 앱 관례).

### 3.3 형태·간격·머티리얼

- **모서리:** 연속 곡률 사용 `RoundedRectangle(cornerRadius:, style: .continuous)`. 반경은 4단계: 10(작은 칩) / 14(썸네일, 입력) / 20(카드) / 시스템(시트, 동심원 원칙으로 기기 모서리에 맞춤).
- **간격:** 4pt 그리드(4/8/12/16/20/24). 좌우 기본 여백 16, 터치 영역 최소 **44×44pt**.
- **머티리얼:** 카메라 위 컨트롤 `.ultraThinMaterial`, 내비게이션/탭 바 `.bar`(시스템 기본), 시트 `.regularMaterial`. iOS 26에서는 시스템 컴포넌트가 자동으로 Liquid Glass를 쓰고, 직접 만든 플로팅 컨트롤만 `glassEffect()`를 쓰되 iOS 17~25에서는 머티리얼로 대체한다.
- **접근성 설정 대응:** 투명도 감소가 켜지면 머티리얼은 불투명 배경으로, 동작 줄이기가 켜지면 줌 전환과 숫자 롤링은 페이드로 대체한다.

## 4. 사용자 흐름

```
[앱 실행] → Camera 탭
   ├─ 필름 모드 & 롤 없음 ──→ "NO FILM" 안내 ──→ 필름 버튼 → Film Drawer 시트
   │        └─ 필름 선택 → 24/36 선택 → [장전] → 확인 대화상자 → 롤 장전 → 촬영
   ├─ 필름 모드 & 롤 있음 ──→ 촬영 (남은 장수 카운트 다운, 사진은 보이지 않음)
   │        └─ 마지막 장 ──→ Develop 전체 화면 → 갤러리 내보내기 → [새 필름] / [단일로 계속]

Settings 탭 → 격자, 날짜 각인, 햅틱, 저장 안내, 초기화
```

## 5. 핵심 화면 5개

기호: `▢` 버튼, `◉` 셔터, `[ ]` 입력/세그먼트, `▒` 머티리얼 배경.

### 5.1 Camera (뷰파인더)

```
┌─────────────────────────────┐  ← 상태 바 / 다이내믹 아일랜드 (세이프 에어리어 = 비워 둠)
│ ░░░░░░  (safe area top)  ░░░░│
│        ▒ [ 필름 | 단일 ] ▒   │  ← 모드 세그먼트 (머티리얼 캡슐), 아일랜드 아래 8pt
│ ╭─────────────────────────╮ │
│ │ GOLD 200 · 20/24   ▒    │ │  ← caption, 머티리얼 칩 (좌상단)
│ │                         │ │
│ │       뷰파인더 4:3       │ │  ← 연속 곡률 모서리, 좌우 세이프 에어리어 안
│ │       (LUT 실시간)       │ │     [그리드 on이면 3×3 선]
│ │                         │ │
│ │                '26 10 07│ │  ← 날짜 각인 (설정에서 on/off)
│ ╰─────────────────────────╯ │
│  [ ▢ film ]   ◉    [ 20 ]   │  ← 필름 버튼 / 셔터 72pt / 프레임 카운터
│  골드                남음    │
├─────────────────────────────┤
│  📷 Camera  ▫Library  ⚙Set  │  ← Tab Bar (.bar), 홈 인디케이터 위
└─────────────────────────────┘
```

- **배치:**
  - 모드 세그먼트는 상단 세이프 에어리어 바로 아래에 둔다. 아일랜드 영역은 침범하지 않는다.
  - 셔터는 72pt 원형이고 탭 바 바로 위 중앙이다(엄지 영역). 좌측은 필름 버튼(`film` 심볼 + 필름 이름), 우측은 프레임 카운터다.
  - 필름 모드에서 롤이 장전된 동안 필름 버튼에는 `lock.fill`이 붙고, 탭하면 시트를 열되 선택은 막힌다.
- **상호작용:**
  - 모드 세그먼트 탭 → 모드 전환. 필름 모드에서 롤이 없으면 뷰파인더 위에 "필름을 골라 넣어 주세요" 안내와 `▢ 필름 고르기`(prominent)가 머티리얼 카드로 뜬다.
  - 셔터: 필름 모드(롤 없음)면 시트 대신 상단 인라인 배너("필름을 먼저 넣어 주세요"). 롤이 있으면 촬영 → 카운터가 숫자 롤링으로 감소.
  - 마지막 장이면 0.65초 뒤 Develop 전체 화면(§5.4).
  - 필름 모드에서는 촬영 직후 썸네일 프리뷰를 **보여 주지 않는다**("현상 전"의 핵심).
- **햅틱:** 셔터 `.impact(.medium)`, 필름 모드 마지막 장 `.success`, 롤 없을 때 셔터 `.warning`, 모드 전환 `.selection`.
- **HIG 근거:**
  - Clarity: 컨트롤 4개, 라벨은 SF Pro Text Style.
  - Deference: 뷰파인더가 화면의 대부분을 차지하고 컨트롤은 반투명이다.
  - Depth: 머티리얼 칩이 뷰파인더 위에 떠서 층이 구분된다.
  - 다이내믹 아일랜드와 홈 인디케이터 영역에 컨트롤이 없다.
  - 셔터는 엄지 도달 영역이고 터치 영역은 44pt 이상이다.
- **접근성:** 셔터는 `accessibilityLabel("셔터, 남은 20장")`. 카운터는 숫자 변경 시 VoiceOver 알림. 롤 잠금 상태를 색이 아닌 아이콘과 텍스트로 전달한다.

### 5.2 Film Drawer (필름 선택·장전, 시트)

```
        (Camera 화면이 뒤에 비쳐 보임)
┌─────────────────────────────┐
│          ━━ (grabber)        │
│  필름 서랍                 ✕  │  ← Navigation Bar (시트 안), 큰 제목 없음 (.inline)
│  넣을 필름을 하나 꺼내세요     │  ← subheadline, secondaryLabel
│ ┌─────────────────────────┐ │
│ │ [통]  텅스텐        ◯    │ │  ← 행: 필름 통 일러스트(콘텐츠) / headline / 선택 표시
│ │       푸른 그림자…       │ │     subheadline
│ ├─────────────────────────┤ │
│ │ [통]  골드          ✔    │ │  ← 선택됨: checkmark.circle.fill (틴트)
│ ├─────────────────────────┤ │
│ │ [통]  포레스트  🔒       │ │  ← 롤 장전 중이면 lock.fill + 흐린 글자
│ └─────────────────────────┘ │
│  롤 길이   [ 24장 | 36장 ]    │  ← 세그먼트 (필름 모드, 롤 없음일 때만)
│  ┌─────────────────────────┐│
│  │    골드 24장 장전하기    ││  ← .borderedProminent (틴트), 높이 50
│  └─────────────────────────┘│
│  넣으면 다 찍을 때까지 바꿀    │  ← footnote, tertiaryLabel
│  수 없고, 사진은 롤이 끝나면…   │
└─────────────────────────────┘
```

- **배치:**
  - 시트는 `.presentationDetents([.medium, .large])`, `.presentationBackground(.regularMaterial)`, 그래버 표시.
  - 단일 모드에서는 "하나 꺼내서 바로 바꿔 끼워요"가 부제이고, 선택 즉시 시트가 닫힌다(장전 버튼 없음).
- **상호작용:**
  - 행 탭 → 선택 표시 이동. 잠긴 행 탭 → 행이 좌우로 짧게 흔들리고(동작 줄이기에서는 생략) 인라인 배너로 "롤을 다 찍어야 바꿀 수 있어요 · 남은 N장".
  - `장전하기` 탭 → **확인 대화상자**(`confirmationDialog`): "골드 24장을 장전할까요? 다 찍을 때까지 필름을 바꿀 수 없어요." [장전] / [취소].
  - 확인 후에는 시트가 닫히고 Camera로 돌아온다. 아래로 스와이프해서 닫기도 가능하다.
- **햅틱:** 행 선택 `.selection`, 잠긴 행 탭 `.warning`, 장전 확인 `.success`.
- **HIG 근거:**
  - 되돌릴 수 없는 결정(롤 잠금)은 확인 대화상자로 한 번 더 확인한다.
  - 시트는 목록 선택처럼 한 가지 작업에 집중할 때 쓰는 표준 모달이다.
  - 선택은 틴트 색만이 아니라 체크 마크로도 전달한다.
  - 필름의 고유 색은 일러스트로만 쓰고 UI 틴트와 분리한다.

### 5.3 Library (사진)

```
┌─────────────────────────────┐
│ ░░░░ (safe area top) ░░░░░░░│
│ Library                      │  ← Large Title (스크롤하면 .inline으로 접힘, .bar 머티리얼)
│ [ 롤 | 단일 촬영 ]            │  ← 세그먼트
│                              │
│ 현상 대기 중                  │  ← title2
│ ┌─────────────────────────┐ │
│ │ [통] 골드 · 14 / 24장    │ │  ← 사진은 보여 주지 않음
│ │ ▮▮▮▮▮▮▮▮▮▮▮▮▮▮▯▯▯▯▯▯▯▯▯▯ │ │  ← 진행 슬롯(채움/외곽선), accessibilityValue "14장, 24장 중"
│ │ 다 찍으면 현상돼요        │ │  ← footnote
│ └─────────────────────────┘ │
│                              │
│ 골드 24장          10월 7일   │  ← 현상된 롤 헤더
│ ┌───┬───┬───┐               │
│ │   │   │   │               │  ← 3열 그리드, 간격 2, 썸네일은 정사각 크롭 없이 3:4
│ ├───┼───┼───┤               │
├─────────────────────────────┤
│  ▫Camera  📷Library  ⚙Set   │
└─────────────────────────────┘
```

- **배치:** 큰 제목 + 세그먼트 → 현상 대기 카드 → 롤 섹션(헤더는 `.title3`급, 날짜는 footnote) → 3열 그리드. 단일 촬영 탭은 3열 그리드(최신순) 하나다.
- **상호작용:**
  - 썸네일 탭 → Roll Detail/Photo Viewer로 **줌 전환** 푸시. 왼쪽 가장자리 스와이프로 뒤로 가기.
  - 썸네일 길게 누르기 → **컨텍스트 메뉴**(시스템 머티리얼): 공유(`square.and.arrow.up`), 사진 앱에서 보기, 삭제(`trash`, 파괴적).
  - 현상 대기 카드는 탭해도 사진을 열지 않는다. 진행 상태만 보여 준다.
- **햅틱:** 컨텍스트 메뉴 열림 `.impact(.medium)`(시스템), 삭제 확정 `.warning`.
- **HIG 근거:**
  - 큰 제목은 탭의 최상위에서만 쓰고 스크롤 시 표준 동작으로 접힌다.
  - 사진 그리드는 콘텐츠가 주인공이라 장식이 없다.
  - 컨텍스트 메뉴는 보조 동작을 숨기되 즉시 발견할 수 있게 하는 표준 패턴이다.
  - 삭제는 파괴적 스타일이고 확인 단계를 둔다.

- **배치:** `fullScreenCover`로 표시하고, 하단 버튼은 홈 인디케이터 위 세이프 에어리어 안에 둔다. 갤러리 내보내기 중에는 `ProgressView`와 "사진을 사진 앱으로 옮기는 중이에요" 문구를 보여 주고, 완료 후 본문이 바뀐다.
- **상호작용:**
  - 프레임은 `brightness` 과노출 → 정상 + 스케일 .85 → 1로 순차 등장(동작 줄이기에서는 페이드).
  - 프레임 탭 → Photo Viewer.
  - `새 필름 고르기` → 전체 화면을 닫고 Camera에서 Film Drawer 시트를 연다.
  - `단일 촬영으로 계속 찍기` → 모드를 단일로 바꾸고 닫는다.
  - 내보내기가 실패하면 알림 대신 인라인 오류 + `다시 시도`를 보여 주고, 앱을 다시 열어도 이어서 시도한다.
- **햅틱:** 현상 완료 `.success`(한 번), 프레임 등장에는 햅틱을 쓰지 않는다(과한 피드백 방지).
- **HIG 근거:**
  - 한 번뿐인 감정적 순간이라 모달 전체 화면이 적합하다.
  - 주 행동은 prominent 버튼 하나이고 보조 행동은 plain 버튼이라 위계가 분명하다.
  - 완료 상태는 색이 아니라 텍스트와 아이콘으로 전달한다.

- **HIG 근거:**

  - 정책(데이터 삭제 시 롤 초기화)은 푸터로 정직하게 알린다.
  - 위험 동작은 분리, 파괴적 스타일, 확인 단계의 세 가지로 보호한다.

## 6. 햅틱 요약

| 이벤트 | 피드백 | API 예 |
|---|---|---|
| 셔터 | impact medium | `.sensoryFeedback(.impact(weight: .medium), trigger: shotCount)` |
| 필름 모드 마지막 장 / 현상 완료 | success | `.sensoryFeedback(.success, trigger: rollFinished)` |
| 모드 전환, 필름 행 선택, 토글 | selection | `.sensoryFeedback(.selection, trigger: mode)` |
| 롤 없이 셔터, 잠긴 필름 탭 | warning | `.sensoryFeedback(.warning, trigger: blockedTap)` |
| 파괴적 확정(삭제, 초기화) | warning | 확인 대화상자의 확정 시점 |

- 햅틱은 설정에서 끌 수 있다. 시스템 햅틱 설정이 꺼져 있으면 따라간다. 연속 동작(프레임 등장)에는 쓰지 않는다.

## 7. 접근성 체크리스트

- Dynamic Type: 모든 텍스트는 Text Style. 가장 큰 접근성 크기에서도 레이아웃이 가로 스크롤 없이 줄바꿈된다(카운터와 라벨은 `minimumScaleFactor` 대신 세로 배치 전환).
- VoiceOver: 롤 진행 슬롯은 하나의 요소로 묶어 "14장, 24장 중"으로 읽는다. 필름 통 일러스트는 장식이므로 숨기고 행 전체에 라벨을 준다.
- 색에만 의존하지 않기: 선택, 잠금, 오류는 아이콘과 텍스트를 함께 쓴다.
- 대비: 틴트와 모든 글자 색은 4.5:1 이상. 고대비 변형을 Asset Catalog에 정의한다.
- 투명도 감소, 동작 줄이기, 볼드 텍스트, 버튼 모양 표시 설정을 모두 지원한다.

## 8. 구현 순서 제안

1. 공통: 상태 머신과 SwiftData 스키마, LUT 큐브 파서(.cube → 33³), 단위 테스트(안드로이드판의 롤 엔진 테스트와 같은 케이스를 이식).
2. Camera: 세션 + LUT 프리뷰 → 촬영(LUT, 필름 모드 그레인) → 저장.
3. Film Drawer와 롤 장전·잠금 → 카운트 감소(저장 성공 후).
4. Develop와 PhotoKit 내보내기(전부 성공해야 완료, 재시도).
5. Library, Photo Viewer, Settings, 접근성과 현지화 점검.

## 9. 이 문서의 한계

- 구현하거나 기기에서 확인한 것이 아니다. 특히 프리뷰 LUT 성능, iOS 26 Liquid Glass 모양, 틴트 대비값(계산값)은 구현 후 실기기에서 검증해야 한다.
- SF Symbols 이름은 가장 흔한 것을 골랐으며, 일부는 OS 버전별 가용성을 SF Symbols 앱에서 확인해야 한다.
- 필름 3종의 LUT는 현재 임시 복사본이다(안드로이드판과 동일). 실제 `.cube`가 준비되면 교체한다.
