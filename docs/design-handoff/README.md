# Handoff: phone_film — 안드로이드 필름 카메라 앱

## Overview
필름 카메라 색감(3D LUT)을 실시간 프리뷰와 촬영 결과물에 적용하는 안드로이드 카메라 앱. 두 가지 촬영 모드가 있다.

- **필름 모드(FILM)**: 필름(프리셋) 1개 + 24/36장을 장전하면 다 찍을 때까지 다른 필름으로 바꿀 수 없다. 찍은 사진은 **롤이 끝나야 한꺼번에 "현상"되어 보인다.** 남은 장수는 프레임 카운터 다이얼에 표시된다.
- **단일 촬영(SINGLE)**: 잠금 없이 필름을 자유롭게 바꾸고, 찍은 사진을 바로 볼 수 있다. 진행 중인 필름 롤은 멈춘 상태로 유지된다.

기준 디자인은 **2a(variant = `silver`)**: 실버 탑 플레이트 + 블랙 뷰파인더 영역 + 다크 브라운 하단.

## About the Design Files
이 폴더의 파일은 **HTML로 만든 디자인 레퍼런스(프로토타입)**다. 의도한 모양과 동작을 보여 주는 것이고, 그대로 출시할 프로덕션 코드가 아니다. 할 일은 이 HTML 디자인을 **실제 안드로이드 앱 환경에서 다시 구현하는 것**이다(아래 권장 스택 참고).

- `Phone Film.dc.html`: 옵션 비교 캔버스(1a/1b/1c/2a). 브라우저에서 열면 바로 동작한다(로컬 서버 권장: `npx serve .`).
- `PhoneFilmApp.dc.html`: 앱 본체 프로토타입. 모든 화면, 상태, 로직이 들어 있다. `variant` prop으로 카메라 화면 레이아웃이 바뀌며 **`silver`가 최종안**이다. 로직은 파일 하단 `class Component` 안에 있다.
- 프로토타입의 "필름 색감"은 CSS filter와 블렌드 레이어로 흉내 낸 것이다. 실제 앱에서는 **.cube 3D LUT**로 대체해야 한다.

## Fidelity
**High-fidelity.** 2a 카메라 화면은 색, 치수, 인터랙션이 확정 상태다. 필름 선택, 롤 길이, 롤 종료(현상), 갤러리, 설정 화면은 흐름과 기능은 확정이지만 스타일은 아직 이전 톤(흰/회색 그레인 배경 + 실버 포인트)이다. 2a의 실버 × 블랙 언어에 맞춰 정리하는 것을 권장한다.

## 권장 기술 스택
**Kotlin + Jetpack Compose + CameraX + OpenGL ES 3.0**

- 실시간 프리뷰 LUT: CameraX `Preview` → `SurfaceTexture`(OES 텍스처) → GLES 프래그먼트 셰이더에서 `sampler3D`(33³ LUT, `GL_LINEAR` 보간)로 샘플링 → `GLSurfaceView`/`TextureView`에 출력. 1080p 기준 프레임 드랍 없이 처리된다.
- 촬영 결과물: `ImageCapture`로 받은 비트맵을 같은 셰이더로 오프스크린(FBO) 렌더링한 뒤 JPEG로 저장한다. 프리뷰와 결과물이 같은 LUT를 공유하므로 색이 일치한다.
- 영구 저장: 롤 상태는 Room 또는 DataStore에 저장한다. 사진은 앱 전용 저장소에 두고, 현상 시 MediaStore로 내보낸다.
- 대안: Flutter(UI와 롤 로직) + 네이티브 Kotlin 플러그인(카메라 + GL LUT, `Texture` 위젯으로 전달). Dart를 쓸 수 있다는 장점이 있지만, 결국 GL/카메라 코드는 Kotlin으로 짜야 하고 플랫폼 채널 구조가 하나 더 생긴다.

## LUT 파이프라인 (개발 단계 오프라인 작업)
- `extract_lut.py before.jpg after.jpg film.cube`로 33³ .cube를 추출한다(numpy, pillow, scipy).
- **필름 3종**을 `app/src/main/assets/luts/`에 둔다: `tungsten.cube`, `gold.cube`, `forest.cube`.
- 앱 시작 시 .cube를 파싱해 `GL_TEXTURE_3D`(RGB16F 또는 RGBA8)로 업로드한다. .cube 데이터는 R이 가장 빠르게 변하는 순서이므로 width = R, height = G, depth = B로 매핑한다.
- 아직 검증 안 됨: 사진에 없는 색 영역의 외삽, 밴딩. 여러 장면의 사진 쌍을 합쳐 하나의 LUT로 만드는 모드도 검토가 필요하다.

- 밀착 인화지: 검정 배경에 6열 그리드, 각 프레임 3:4에 프레임 번호(01~)를 붙인다.

- 버튼: "새 필름 고르기"(primary), "단일 촬영으로 계속 찍기"(ghost).

## Interactions & Behavior
- **모드 전환**은 화면을 이동하지 않는다. 카메라 화면에 머문 채 레버만 움직이고 토스트로 알린다.
  - SINGLE → FILM, 롤이 있을 때: "{필름} 롤로 돌아왔어요 · 남은 N장"
  - SINGLE → FILM, 롤이 없을 때: "필름 모드 · 필름을 넣어 주세요"
  - FILM → SINGLE: "단일 촬영 · 필름 롤은 그대로 멈춰 있어요"
- **셔터**
  - 필름 모드: 롤이 없으면 토스트 "필름을 먼저 넣어 주세요". 있으면 shots에 추가하고 카운터를 -1 한다. 마지막 장이면 롤 종료로 간다.
  - 단일 모드: 즉시 저장되고 썸네일이 갱신된다.
- **토스트**: 하단 중앙 pill, `#201e1d` 배경에 밝은 글자, 2.2초 후 사라진다.
- **필름 잠금**: 롤 장전부터 마지막 장까지 필름을 바꿀 수 없다. 롤 종료 시 자동으로 해제된다.

## State Management
```
mode: 'film' | 'single'
roll: { filmId, total: 24|36, shots: Shot[], start } | null   // 필름 모드 진행 롤 (잠금 근거)
singleFilm: filmId
singleShots: Shot[]
devRolls: { filmId, total, shots, start, end }[]   // 현상 완료 롤
settings: { grid: bool, stamp: bool }
UI 전용(저장 안 함): drawerOpen, pendingFilm, pendingLength, toast, viewer
Shot: { filmId, uri, takenAt }
```
- `roll`, `mode`, `singleFilm`, 사진 목록, 설정은 **매 촬영마다 동기적으로 저장**한다(Room 트랜잭션 권장). 강제 종료나 재부팅 뒤에도 유지되어야 한다.
- 재설치하거나 앱 데이터를 지우면 저장소가 비므로 롤이 초기화된다. 이것이 의도한 정책이다. 백업 대상에서도 제외한다(`android:allowBackup="false"` 또는 backup rules).
- 필름 모드 사진은 롤 종료 전까지 앱 내부 저장소에만 둔다. 현상 시점에 MediaStore(갤러리)로 내보낸다. 단일 모드 사진은 즉시 내보낸다.
